# Releasing FurnitureOS

Releases are built and published by `.github/workflows/release.yml` when a tag `v*` is pushed.
Nothing is built on a developer machine; the workflow builds on clean GitHub runners, runs the full
test suite on Windows and Linux, and only then publishes.

## What a release contains

| File | What it is |
|---|---|
| `FurnitureOS-<v>-windows-x64-setup.exe` | Per-user installer (Inno Setup), no administrator rights |
| `FurnitureOS-<v>-windows-x64.zip` | Portable folder (unzip and run) |
| `FurnitureOS-<v>-linux-x86_64.tar.gz` | Linux build against the system Qt 6 (Ubuntu 24.04+) |
| `SHA256SUMS.txt` | SHA-256 of every file above (`sha256sum -c SHA256SUMS.txt`) |
| `update.json` | Metadata read by the in-app updater (format below) |

`<v>` is the full version, e.g. `0.1.0` or `0.1.0-beta.1`.

## Version numbers

The version has one source of truth, the root `CMakeLists.txt`:

```cmake
project(FurnitureOS VERSION 0.1.0 ...)                     # X.Y.Z
set(FOS_VERSION_SUFFIX "" CACHE STRING "...")             # "" or a pre-release suffix such as "-beta.1"
```

CMake combines them into `FOS_VERSION_STRING` (e.g. `0.1.0-beta.1`). It is compiled into the desktop
application (`fos::app::applicationVersion()`: Help ▸ About and `QApplication::applicationVersion`), the
`fos --version` output, the `app.version` field of saved files, and the Windows ProductVersion resource.
The numeric Windows FileVersion uses `X.Y.Z.0` only. A configured build also writes
`build/fos-version.txt`.

* Final release: suffix empty, tag `v0.1.0`, published as a normal (latest) release.
* Test release: suffix `-beta.1`, `-rc.1`, …, tag `v0.1.0-beta.1`, published as a **prerelease**.
  GitHub's "latest release" link ignores prereleases, so an updater that reads
  `releases/latest/download/update.json` does not see them.

The workflow refuses a tag that is not exactly `v` + `FOS_VERSION_STRING` from the committed
`CMakeLists.txt` (`packaging/release/read_version.py --check-tag`).

## Cutting a release

1. **Bump the version** in the root `CMakeLists.txt` (`project(... VERSION X.Y.Z)` and, for a test build,
   the default of `FOS_VERSION_SUFFIX`).
2. **Update `CHANGELOG.md`**: move the items from `[Unreleased]` into a new section
   `## [X.Y.Z] - YYYY-MM-DD` (for a pre-release, `## [X.Y.Z-beta.1] - …`), and update the link references at
   the bottom. The body of that section becomes the release notes and the `notes` field of `update.json`.
   Without a matching section the workflow falls back to the annotated tag message, and fails if there is
   neither.
3. Update `PROJECT_STATUS.md` if the release changes what is claimed there.
4. Commit, push, and wait for CI to pass on that commit.
5. **Optional dry run**: Actions ▸ Release ▸ Run workflow (on the branch). It builds everything and
   uploads the files as a workflow artifact `FurnitureOS-<v>-release` without publishing anything.
   Download it and try the installer on a Windows machine.
6. **Tag and push the tag**:

   ```sh
   git tag -a v0.1.0 -m "FurnitureOS 0.1.0"
   git push origin v0.1.0
   ```

7. Watch Actions ▸ Release. When it is green the release is on the Releases page with all files.

### If something goes wrong

* Tag does not match the version: delete the tag (`git push --delete origin v0.1.0; git tag -d v0.1.0`),
  fix `CMakeLists.txt`, commit, tag again.
* A build or test failure: nothing has been published. Fix, commit, move the tag
  (`git tag -fa v0.1.0 -m …; git push --force origin v0.1.0`) — only while the release does not exist yet.
* Re-running a failed `publish` job replaces the files of an existing release with the same tag.
* Never re-use a version number once a release has been downloaded by anyone; publish `X.Y.(Z+1)` instead.

## Repository settings needed once

* Settings ▸ Actions ▸ General ▸ Workflow permissions: either setting works, because the `publish` job
  requests `contents: write` itself; but if the organisation restricts the token to read-only *and*
  forbids elevation, releases cannot be created.
* Tag protection rules (optional): restrict who may push `v*` tags.

## update.json

```json
{"version":"0.1.0","published":"2026-11-27","notes":"<markdown>",
 "assets":{"windows-x64-zip":{"name":"FurnitureOS-0.1.0-windows-x64.zip","sha256":"…","size":123},
           "windows-x64-setup":{"name":"FurnitureOS-0.1.0-windows-x64-setup.exe","sha256":"…","size":456}}}
```

* `version`: full version string; `published`: ISO 8601 date (UTC) of the workflow run; `sha256`: lower-case
  hex; `size`: bytes. Asset names are files of the same GitHub Release
  (`https://github.com/<owner>/<repo>/releases/download/v<version>/<name>`).
* Generated by `packaging/release/make_release_metadata.py`, which also writes `SHA256SUMS.txt`.

## Windows installer

`packaging/windows/furnitureos.iss` (Inno Setup 6.3+). Inno Setup was chosen over CPack/NSIS because a
per-user installation is a first-class mode (`PrivilegesRequired=lowest`: no UAC prompt, `{autopf}` =
`%LOCALAPPDATA%\Programs`, registry root `HKA` = `HKCU`), the uninstaller, Start-menu entries, the
per-user `.fosp` association, closing a running copy during an upgrade (Restart Manager) and the silent
switches need no custom scripting; CPack's NSIS template assumes machine-wide installation (HKLM, admin).

* Installs to `%LOCALAPPDATA%\Programs\FurnitureOS`, Start-menu shortcut, optional desktop shortcut,
  `.fosp` association (task, on by default), uninstaller in Settings ▸ Apps.
* Writes `installed.txt` next to `furnitureos.exe`; the portable ZIP never contains it. The in-app updater
  uses it to choose between running the setup and pointing to the ZIP.
* Silent install or upgrade (same `AppId`, keeps the chosen folder):
  `FurnitureOS-<v>-windows-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` (add `/LOG="path"` for a
  log). The setup closes a running FurnitureOS; it does not start the application after a silent run
  (`skipifsilent`), so the updater must relaunch it.
* Silent uninstall: `"%LOCALAPPDATA%\Programs\FurnitureOS\unins000.exe" /VERYSILENT /SUPPRESSMSGBOXES`.
* The workflow tests install, upgrade over itself and uninstall silently on the runner.
* **Unsigned.** Neither setup nor executables are code-signed, so Microsoft SmartScreen warns
  ("Windows protected your PC") until the file has built up reputation. Users click *More info* ▸
  *Run anyway* (see `docs/user-guide/installing-windows.md`). Signing needs a code-signing certificate
  (or a service such as SignPath for open-source projects) and is not set up.

Build it by hand on Windows after `cmake --install build --prefix dist\FurnitureOS`:

```bat
ISCC /DAppVersion=0.1.0 /DAppVersionNumeric=0.1.0 /DStageDir=%CD%\dist\FurnitureOS /DOutputDir=%CD%\packages packaging\windows\furnitureos.iss
```
